# Release candidate: manual QA

All cases are **NOT RUN**. Record date, Windows version, app build, and mouse/receiver firmware before testing. Keep logs free of device paths and serial numbers.

- [ ] **NOT RUN — First launch:** Copy the portable EXE to a stable directory and start it. Expected: one tray icon appears (possibly under hidden icons), with an unknown state until a reading arrives. The app does not open a main window. Limitation: first read may fail while the mouse sleeps.
- [ ] **NOT RUN — Battery comparison:** Wake the L7 Ultra+ on its 2.4 GHz receiver and compare a recent reading with MCHOSE HUB at the same time. Expected: values agree or any difference is recorded with timestamps. Limitation: the protocol cannot prove freshness; avoid assuming earlier 85% and 90% readings were simultaneous.
- [ ] **NOT RUN — Refresh:** Choose Refresh battery. Expected: the action temporarily indicates progress and the icon/header update only for an accepted response. Limitation: a native HID call may block.
- [ ] **NOT RUN — Startup:** From a stable published location, enable startup, sign out/in, verify launch, then disable and repeat. Expected: the toggle follows the application's own HKCU Run entry. Limitation: development/build/temp paths are ineligible; a conflicting entry is not replaced.
- [ ] **NOT RUN — Low battery and persistence:** Enable alerts, observe naturally occurring readings at or below 20% and 10%, and restart. Expected: one warning per threshold until recovery above 25%; a first reading at or below 10% produces only critical. Preference and suppression survive restart. Limitation: do not simulate battery state with HID commands; cached replies cannot prove freshness.
- [ ] **NOT RUN — Windows theme:** Switch the Windows system taskbar theme between light and dark. Expected: tray number changes palette within approximately 15 seconds without a new battery request. Limitation: popup stays dark.
- [ ] **NOT RUN — Sleep/wake:** Suspend and resume with the receiver connected. Expected: the old reading becomes stale; a delayed recovery attempts a fresh read. Limitation: Windows/HID timing varies; blocked calls cannot be forcibly cancelled.
- [ ] **NOT RUN — Receiver removal and reconnection:** Remove the receiver, wait for detection, and reconnect. Expected: unavailable display followed by a recovery attempt and normal display only after an accepted result. Limitation: descriptor failures produce unknown state and may delay recovery.
- [ ] **NOT RUN — Rapid reconnect:** Remove and reinsert within three seconds. Expected: events coalesce and a later validation plus recovery is attempted; no stale in-flight reading is accepted. Limitation: device notifications can be delayed or absent.
- [ ] **NOT RUN — Exit and single instance:** Start a second instance, then exit via the menu and restart. Expected: only one icon/instance at a time; exit removes the icon. Limitation: the running executable may lock its file until exit.
- [ ] **NOT RUN — CPU and RAM:** Leave the app running for an extended period, including repeated theme/menu changes. Expected: no persistent CPU load or unbounded memory/GDI growth. Limitation: collect measurements over time rather than relying on a single snapshot.
- [ ] **NOT RUN — Windows notifications:** With Windows notifications allowed, observe natural low-battery alerts; repeat with Focus Assist/notifications disabled. Expected: Windows controls presentation and suppression; no repeated warning every poll. Limitation: balloon delivery is not guaranteed and cannot be validated without real conditions.
